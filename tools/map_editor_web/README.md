# 盘橐城 · 网页地图编辑器

**双击 `打开地图编辑器.command` 就能用**，不需要命令行、不需要装任何东西（只要能上网，three.js 从 CDN 取）。

## 它解决的是什么

之前三版编辑器都被否掉，原因不是功能少，是交互：

1. `scripts/traveler/traveler_placer.gd:402` 的 `_pick_object` 比的是**物体原点**的屏幕距离，
   不碰网格。雪山原点在山脚，山高约 931 px 而容差只有 144 px，只有最下面 15% 能点中。
2. 更糟：点空了**不是没选中，是当场生成一座新模型**（`:522-532` 没有"放置模式"这道闸）。
3. `E/R/T` 接反了 —— C4D 是 E移动/R旋转/T缩放，那份写成 E移动/R缩放/T旋转，
   而它自己的文档 `docs/design/shanhe-luren/traveler-placer.md:35` 还写着「同 C4D」。
4. 数字键 1–9 被占用成选资产，而 C4D 里按住 1/2/3 是平移/缩放/旋转视图。
5. 选中后模型上没有任何高亮，只有山脚三根 0.18 单位粗的细线。

这一版把两个致命件**全部换成现成部件**，不自己发明：

- **选中** = three.js `Raycaster`，打到真网格上取最前面那个。
- **手柄** = three.js 官方 `TransformControls`（和 three.js 官方编辑器同一个部件）。
- 点空白处**只取消选中**，绝不生成东西；放新模型必须先点左下调色板，再点地面。
- 选中有**琥珀色包围盒 + 模型自发光**，看得见。
- 所有操作都有屏幕按钮；键盘只是可选，且 `E/R/T` 严格照 C4D。
- 转镜头是 **Alt + 左键**（C4D 习惯），Alt+中键平移，滚轮推拉。

## 能编辑什么

读 `data/traveler/panti_scene.json`，按类别列出并可编辑：

| 类别 | 数量 | 可改 |
| --- | ---: | --- |
| 雪松 | 54 | 位置、高度、冠幅、转向 |
| 石头 | 30 | 位置、高度、转向 |
| **雪坡块** | 9 | 中心、半径（横/纵）、高度、转向 —— 这就是「生成地形」 |
| 营地道具 | 5 | 相对营地原点的偏移、尺寸、转向 |
| 城堡·人物 | 2 | 位置、高度、朝向 |
| 我导入的 | — | 拖 `.glb/.fbx` 进画面即可 |

地形用的是场景里现成的 9 个椭圆雪坡块（`ground.relief.ridges`），
在画面上显示成青色/橙色椭圆（蓝=凸起，橙=下凹），像模型一样点选、拖动、缩放、旋转。

## 保存的安全性（这是最重要的一段）

`data/traveler/` 下 14 个文件**一个都没有被 git 跟踪**（`git ls-files data/traveler` 返回 0 行，
也没有被 ignore，就是从来没 add 过）。`panti_scene.json` 有 17 个顶层键、7 处 `authorization`
记着 Carlos 的原话、几十条散文说明，**一旦被覆盖没有任何 git 历史可以找回**。
而一次"正常"的全量序列化就能静默删掉整块 `weather`（实测 79 个数值叶子）。

所以保存**永远是「读出来、原地改叶子、写回去」**：

- 只按 `id` / 索引匹配**已有**条目，匹配不到就跳过并在回执里记一条，**绝不新建**；
- 只覆盖明确认领的叶子键，其它键连碰都不碰；
- 自己导入的模型不塞进 Codex 的数组，单独放 `custom_props`；
- 写入前自检顶层键数量，不一致就放弃写入；
- **默认写到 `panti_scene.edited.json` 副本，不动线上文件**。

实测（改一棵树 + 一个雪坡块 + 城堡朝向，并故意塞一个不存在的 id 和一个越界索引）：

```
顶层键 17 → 17          叶子 1303 → 1303
丢失的键 0              新增的键 0
改动的叶子 恰好 12（全是要求改的那几个）
weather 块完好          authorization 7 → 7
不存在的 id / 越界索引：跳过并记账，未静默新建
```

「写入线上」按钮会直接改 `panti_scene.json`，会先自动备份到 `~/SilkRoad-data-backup/`，
并且要二次确认。**Codex 此刻也在写这个文件，同时写有丢东西的风险，所以默认不走这条。**

## 已知边界

- 画面是**预览**，不是游戏最终观感：没有游戏的雪材质、夕阳预设、景深和描边。
  判断构图可以，判断"好不好看"还是要看 Godot 渲出来的图。
- 地形高度场是按 `ground.relief` 的数据**近似复现**的（椭圆叠加 → 路径压平 → 城堡平台），
  不是 `panti_snow_ground.gd` 的逐位复刻。
- 只服务 `assets/traveler` 与 `docs/reports/traveler-panti-001/references` 两棵子树，
  别的路径一律 403（实测 `project.godot` 与场景 JSON 都被挡住）。
- `custom_props` 引擎侧还没有人读，导入的模型目前只是记下来。
- FBX 走 three.js 的 `FBXLoader`：仓库里的 FBX 都是 binary 7200–7700，在支持范围内；
  但外部拿来的 FBX 若贴图是外链文件，浏览器读不到那些贴图，会显示成白模。
