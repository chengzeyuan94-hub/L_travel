# 导入功能数值规则配置，开始商旅对局

下载 [LTravel-functional-rules-v1.json](https://github.com/chengzeyuan94-hub/L_travel/releases/download/v0.2.4-public.1/LTravel-functional-rules-v1.json)，使用现有 **0.2.4-public.1** 游戏即可导入；不需要重新下载完整安装包。

这份 JSON 恢复本项目 r2 功能基线中的玩法功能数据：15种货物供应、16座城市起始物资、8堆共80张贸易牌的交换数值、陆地18张及海洋18张事件的机器效果，以及银库、仓容、骰面和结算参数。地图使用公开包已经包含的16城、54节点、57条连接。文件没有原卡图片、扫描、卡名、故事文字或第三方角色素材；事件标题与操作说明重新撰写。

`generator_params` 是本项目现有的原创v2新增城市生成参数，保持原值。它不替代基础80张贸易牌，不代表桌游作者的官方生成公式，也不构成经济平衡认证。

1. 从本仓库下载规则JSON的原始文件，保留 `.json` 扩展名。不要把 GitHub 网页另存为JSON。
2. 打开游戏或地图工坊，点击右下角 **配置玩法规则 → 导入已确认的规则文件**，选择该文件。
3. 界面应显示“规则已保存”。退出后重新打开游戏/工坊，让已打开地图按新规则校验。
4. **新建商旅对局**，设置2–4位商人后开局。基础棋盘已经在程序内，无需另导入地图。验证时先用两位真人，确认地图、起始物资、当前城市贸易牌可见，再完成掷骰、移动、交易与结束回合。
5. 工坊中的新建/已有地图应重新校验后再试玩。自定义地图仍走其专门地图入口；本规则文件不是地图文件。新增城市的生成牌堆仍需通过工坊自身校验。

高级JSON入口可粘贴同一个文件。格式为 `lshu.rules.config.v1`，小于1 MiB。不要把 `trade_decks.json`、`event_definitions.json` 或 `release-manifest.json` 单独当作规则配置导入；它们不是这个入口接受的完整结构。

本文件的全部城市和商品ID与公开包匹配；每张贸易牌4个资源条目，每个事件模板生成1张实例，两堆各18张。规则入口不导入城市拓扑、模型、图片、音轨或扩展包；因此也不包含私人18城规划地图。不同地图的基础身份、交通拓扑、商品和牌堆兼容性仍需独立验证。

2026-10-19验证：使用与公开包冻结源码一致的规则脚本，在独立数据目录完成真实 `PublicRules.install`、正式校验、2/3/4人开局、36张事件逐张结算与回合继续；三局随机电脑流程累计369个玩家回合、98次交易、56次随机事件面，货物总量和货仓一致性检查通过。三局均在120回合后调用现有“时间到”终局入口，并补齐本轮完成结算；不是自然耗尽银库的整局，也不是经济平衡测试。没有完成本轮GUI鼠标、Windows或Android实机验证。机器摘要见 [RULES-VALIDATION.json](RULES-VALIDATION.json)，文件摘要见 [SHA256SUMS](SHA256SUMS)。

现版已知边界保持：骰子固定为1–5加事件面；本文件与此一致并完整提供陆海事件。原版城市起始物资均为单项，本文件不触发已知多项重领缺陷。旧存档未固化规则，导入或更换规则后请新开一局进行验收。勿将本配置的通过结果推广为任意JSON都能安全运行。
